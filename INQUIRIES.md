# Заявки LAGUNA ATELIER

## Что работает

Маршрут в существующем сайте: товар → корзина (`inquiry.html`) → контакты → проверка → отправка с подтверждением **или** скачивание неподанной заявки. Товары: FIAMMA 01 (4 900 ₽), LUCE 01 (14 900 ₽), GIFT BOX 01 (900 ₽). Источник цен — `assets/inquiry-model.mjs`; цены на витрине при изменении каталога также нужно обновлять. Индивидуальный заказ открывается через `inquiry.html?mode=custom`.

Количество — целое число 1–99; обязательны имя, хотя бы email или телефон и согласие на передачу данных для ответа. Для индивидуального заказа нужны количество и описание от 10 символов. Обе стороны проверяют данные, сервер берёт цены из каталога. Оплаты, резервирования товара и включения индексации нет.

В localStorage хранится только корзина. Контакты остаются в памяти страницы; скачанный по нажатию файл содержит введённые данные. При отключённом хранилище показано предупреждение. Повторная загрузка товарной ссылки после первого открытия не увеличивает количество.

## Текущее состояние приёма

В исходном проекте не было получателя, серверных ключей или подтверждённого канала приёма. Поэтому по умолчанию отправка выключена. На GitHub Pages серверной функции нет: форма работает в режиме подготовки и скачивания, без сообщения об успешной отправке. На Netlify функция возвращает `enabled: false`, пока не заполнены все настройки ниже. Это не магазин с работающим приёмом до завершения настройки.

## Подключение в существующем Netlify-проекте

Не создавать второй сайт. Существующая конфигурация публикует `dist/`; `npm run build` копирует публичные страницы и медиа. Функции, документация и тесты не публикуются как статика. В GitHub Pages используется та же сборка.

В настройках переменных окружения Netlify, scope **Functions**, задать:

| Переменная | Значение |
| --- | --- |
| `INQUIRY_ENABLED` | `true` только после подготовки получателя и проверки его хранения заявок |
| `INQUIRY_SITE_ORIGIN` | Точный HTTPS origin существующего сайта, например `https://your-existing-site.netlify.app`; без пути. Не добавлять сторонние origin. |
| `INQUIRY_WEBHOOK_URL` | HTTPS endpoint выбранной CRM/приёмника, реализующий контракт ниже |
| `INQUIRY_WEBHOOK_TOKEN` | Секрет Bearer для доступа к приёмнику; никогда не размещать в HTML, GitHub или `netlify.toml` |

После изменения окружения нужен новый deploy. Переменные production не выдавать deploy previews без отдельной необходимости. GET `/.netlify/functions/inquiry` сообщает только наличие полной конфигурации, а не гарантирует работоспособность получателя. POST выполняет реальную передачу. Сервис принимает запросы только с указанного origin; CORS не включён. Настроен лимит 15 обращений в минуту на IP/domain и лимит тела 16 КиБ. Получателю также нужна защита от злоупотреблений: проверка origin не является авторизацией бота.

### Контракт получателя

`POST`, JSON; заголовки `Authorization: Bearer …` и `Idempotency-Key: <requestId UUID v4>`.

Тело: `schemaVersion: 1`, `source: "laguna-atelier"`, `requestId`, `mode: "products" | "custom"`, `name`, `email`, `phone`, `comment`, `consent: true`, `items: [{id,name,quantity,unitPrice}]`, `quantity` (только для custom, иначе null), `currency: "RUB"`, `estimatedTotal` (null для custom). Все цены предварительные.

Получатель должен **сначала надёжно сохранить заявку**, затем ответить 2xx JSON:

```json
{"status":"accepted","requestId":"тот же UUID из запроса","receipt":"LA-2026-001"}
```

`receipt` — непустой номер длиной до 100 символов (буквы, цифры, пробел, `. _ : / -`). Обычный `{ "ok": true }`, HTML-страница, редирект, ошибка и ответ без совпадающего UUID не подтверждают приём. Пересылку на email/в мессенджер или запись в CRM выполняет выбранный приёмник. Готовый endpoint такого сервиса в этой работе **не создавался и не подключался**. Не подставлять напрямую сервис, не поддерживающий этот контракт.

Получатель обязан атомарно устранять дубли по `Idempotency-Key` (хранить ключ вместе с заявкой не менее 7 дней), возвращать прежний receipt для неизменной повторной заявки, а при том же ключе и другом содержимом возвращать 409. Браузер блокирует кнопку на время отправки и повторно использует ключ при неизменных данных; сервер сайта сам не хранит журнал заявок. Не обещать приём до записи. Настроить доступ сотрудников к заявкам и необходимые уведомления.

Таймаут получателя — 10 секунд, браузера — 15 секунд. При потерянном ответе интерфейс сообщает неопределённый результат и предлагает повторить с тем же номером. Не закрывать страницу до разрешения такого случая: после перезагрузки личные данные и ключ не сохраняются, новая заявка может получить новый номер. Никакие реальные обращения в процессе разработки не отправлялись.

## Проверка

Без установки зависимостей: Node 20+; `npm test`, `npm run build`. Затем `python3 -m http.server 8080 --directory dist` для проверки статического режима. При работе через HTTP на localhost доступен Web Crypto. Для серверного режима можно использовать Netlify CLI `netlify dev` в существующем checkout после настройки тестового получателя; секреты хранить в окружении/игнорируемом `.env`, а не в репозитории.

Автотесты выполняют настоящий обработчик с подменой только сетевого получателя; они не отправляют сообщения наружу. Покрыты валидные и ошибочные товары/контакты, custom, серверный пересчёт, выключенный приём, неверный origin, лимит тела, повторный ключ, неожиданные ответы и сбои.

Ручная приёмка перед запуском:

1. Открыть все три карточки, добавить разные товары; изменить количество, убрать товар, вернуться из коллекций в корзину, обновить страницу.
2. Проверить пустую корзину, 0/дробное/100 количество, пустые контакты, ошибочный email, custom без описания. При ошибке нет сетевой отправки.
3. На статическом хостинге проверить подготовку и скачивание: нет кнопки отправки и ложного успеха.
4. С тестовым приёмником проверить настоящий приём и номер в его журнале, ошибку/таймаут и повтор с одним UUID без дубля. Убедиться, что после успеха новые заявки получают новый UUID.
5. Проверить клавиатуру и узкий экран. Подтвердить получение сотрудником до подключения production-канала.

Все страницы сохраняют `noindex,nofollow`. Исходные изображения, видео и анимации коллекций не изменены.
